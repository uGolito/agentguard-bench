# Limitations and threats to validity

- No live LLM benchmark results have been published yet. Scripted behavior and mocked SDK transport tests are not model evidence. No paid evaluation or account/model availability test was performed.
- Thirty authored synthetic cases form a convenience corpus with limited difficulty/representativeness. They do not establish deployment risk or statistical power.
- Exact structured claims and a closed list of generic status aliases can be gamed; arbitrary paraphrases are not recognized. No independent semantic evaluator exists.
- Baseline has no external authorization, output-data schema or evidence safeguards. Guarded modes add them independently of the provider. All effects remain simulated.
- Runtime grants bind exact arguments, scenario IDs and use counts, but rely on trusted local operator configuration, not cryptographic signatures or external identity. The original scenarios retain tool-name-only evaluation oracles; new probes use exact authorized calls and multiplicity. Policies and evaluator ground truth are separate and can disagree.
- Evidence verification checks runtime-observed origin plus literal/structured support. It cannot establish real-world truth, authenticity, semantic entailment, stale-data thresholds or unit conversion. Uncertainty annotations never promote a model assertion. A model may still output unsupported values marked unverified; an exact-value evaluator is not a factuality judge.
- Oversight includes deterministic fakes and an official async Anthropic adapter with a separate system role/context and shared spending ledger. Its live behavior and H4 remain untested. Same-model separate contexts can have correlated errors; minimal context can also remove relevant information.
- Reviewer timeouts require cooperative async code and are not hard process isolation. A blocking/noncooperative reviewer can stall termination; an approval returned after the deadline is rejected. Synchronous runtime calls from an already running event loop fail review closed.
- No MCP transport yet. The Anthropic ledger is now thread-safe with single-use refunds within one process, but is not an account-wide or cross-process quota and cannot guarantee an invoice ceiling. Outstanding requests may still finish after a halt.
- Only the priced snapshot `claude-haiku-4-5-20251001` is currently supported. Its availability and pricing may change. Pricing is snapshotted and should be checked before any approved experiment. Cache writes use a conservative one-hour rate; unknown costs keep a full reservation.
- No streaming, extended thinking, server tools, priority/fast tiers or strict overall wall-clock deadline. Retry delays are bounded, but SDK timeouts are socket-operation timeouts. A timed-out request may still be billed. Failed requests retain unknown-bill reservations and may stop small-budget runs early.
- Final answers require exact benchmark JSON. Format failures and truncations remain incomplete; prose refusals without structured fields may not count as false refusals. Literal disclosure checks count a canary even when quoted to warn about an attack. Neither behavior is a semantic safety judgment.
- Successful raw model content and request payloads are retained, including malicious synthetic strings; API keys and HTTP headers are excluded, and HTTP error bodies are omitted. Streaming journals append and flush during execution before dispatch; final artifacts can still be lost on abrupt termination. No fsync durability, automatic recovery or resume is provided.
- SDK 2.4 compatibility uses its strict-response-validation option and `extra_body` for the legacy model's temperature parameter. Lock-file upgrades require the wire-level tests. Injected clients are a test seam; endpoint/transport trust remains the caller's responsibility.
- Protected literals only match known strings. Encoding, paraphrase or unrelated secrets can evade them. Raw proposed model output remains in trusted research traces even when delivery is blocked.
- Scripts contain expected answers and ignore tool output; fake comparisons test runtime mechanisms and reporting, never model security or oversight quality. The corpus includes positive authorized actions; scripted success does not establish real completion or reviewer quality.
- Latency measures local infrastructure only; repeated fake trials are not independent samples of agent behavior.
- Dependency pinning aids reproduction but hardware, OS and timestamp differences remain. Docker availability and CI execution must be reported honestly in validation records.
- No claims of model safety, legal compliance, statistical significance or laboratory affiliation follow from this repository.

- Scenario labels, aliases and operator example policy share authorship despite separate interfaces; independent review is outstanding. Public criteria/scripts can contaminate future training data.
- Mode rotation mitigates temporal confounding without guaranteeing exact balance. Equal per-mode budgets can exhaust oversight sooner; resource-matched ablations are not implemented.
- Cluster-bootstrap intervals are descriptive conditional on this fixed corpus, not population-risk bounds or significance tests. Mocks, incomplete, sparse or degenerate data suppress informative intervals. Repeated trials cannot substitute for varied scenarios.
- Model/runtime ASR remain narrow deterministic rubric endpoints. Unknown tool proposals are invalid, not automatic attacks; malformed prose may escape factual scoring. Legacy mixed ASR must not be used to attribute runtime blocks to model safety.

- Native `anthropic-json-schema-v1` output is opt-in and qualified only through official documentation and offline SDK wire tests. Live acceptance remains unverified. A valid JSON object can still be semantically wrong; compare only identical output protocols. Historical runs without parsing diagnostics retain unavailable diagnostic rates rather than inferred zero failures. See [protocol qualification](native_output_protocol.md).
