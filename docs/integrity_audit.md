# Milestone 4A evaluation-integrity audit

This is a software/design audit, not independent certification or empirical model evaluation.

## Leakage and controls

Scenario/tool data is deep-copied per episode. Paired scheduling creates new provider/reviewer contexts and retains scenario/trial/mode order. Tests mutate returned fixtures and verify originals remain unchanged. Gold criteria, fake scripts and grants are excluded from primary requests. Reviewer payloads contain only the trusted objective and proposed action data, not the primary transcript, fixture oracle or grant metadata. Public scripts/labels may nevertheless enter future training data: this is not a secret held-out corpus.

Comparisons check prompt, parameters, fixtures, policy, model metadata and caps. Guard envelopes, errors and reviewer consumption are explicit treatment differences. Rotation reduces but cannot remove service/time drift. Equal caps can exhaust C earlier; report this instead of concealing it. Scenario labels and example policy share authorship despite separate runtime/evaluator interfaces. Independent review remains required.

## Classification

Unsafe proposals and executed effects are distinct. Blocked proposals remain model-level behavior, not executed actions. Unknown tool names are invalid proposals, not automatic attack successes. Benign wrong facts do not enter ASR denominators. Extra/wrong claims and citations fail completion. Positive email/update controls prevent blanket refusal from passing.

Exact values, closed uncertainty aliases and provenance rubrics can reject correct paraphrases and miss unsupported prose. No general semantic judge is claimed. Reports preserve counts, zero-denominator nulls, category results and failures without a composite score. Legacy mixed ASR is explicitly labeled. Cluster intervals retain repeated-trial dependence; mocks, partial designs and degenerate/sparse data do not generate misleading certainty.

## Accounting and traces

Primary/reviewer share one budget per mode. Atomic single-use reservation tokens prevent concurrent overspend and duplicate refunds; mismatched ledger configuration is rejected. Retries reserve separately and hidden SDK retries are disabled. Valid usage settles even for malformed verdicts; cancellation and unknown bills retain charges. Reviewer totals use ledger snapshots, not model-supplied billing fields. Estimates do not guarantee invoices or account-wide quotas.

Streaming journals append and flush before dispatch, retain raw responses/results/decisions and deduplicate event IDs. Tests inspect events before final reporting. HTTP credentials/headers are excluded. Hardware/process failure can still lose OS buffers or final summaries; no automatic recovery is promised. Before interpreting live results, reconcile the schedule, journal, final traces and ledger.

## Regression preservation

All original 135 regression cases remain. Tests assuming three scenarios explicitly select byte-preserved tests/fixtures/milestone3 assets. One trace assertion now locates tool_result semantically because proposal tracing adds an earlier event. New tests exercise the real 30-case corpus, repeated A/B/C, isolated state, partial qualification, statistical mathematics and mocked official primary/reviewer SDKs. Socket/DNS guards prevent accidental model calls. Passing tests establishes implementation behavior only.

## Outstanding review

Independently review labels and grants, freeze endpoints/sample size, assess corpus selection/difficulty, recheck pricing/model availability and approve a small service qualification before confirmatory work. Preserve unsuccessful trials. Human scoring agreement, semantic grading, safeguard ablations, out-of-distribution attacks and live service qualification remain unperformed.
